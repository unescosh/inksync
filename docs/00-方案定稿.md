# inksync 方案定稿（v1.0）

> 状态：已与 Ryou 确认四项卡架构决策，方案锁定。待「开始」指令后进入实现（Agent 模式，定稿前不写业务代码）。

## 1. 环境前提与约束
- 目标三端：Android（arm64）/ Windows 10（x64）/ 统信 UOS 20（1070，内核 4.19）。
- UOS CPU 已确认为 **x86_64** → Flutter 官方 Linux 支持，**无需 Qt 降级**。
- 🔴 **硬约束（Ryou 明确）**：UOS 20 基于 Debian 10，**glibc 2.28**。任何链接更高版本 glibc 的产物会**直接打不开或打开无响应**，不是「可能不兼容」。因此 UOS 产物必须全程针对 glibc 2.28 构建：
  - **Rust 核心 cdylib**：用 `cargo zigbuild --target x86_64-unknown-linux-gnu.2.28`（zig 自带 2.28 符号，无需 Debian 10 容器）；或直接在 `debian:10` 容器内 `cargo build`。
  - **Flutter engine**：官方预编译 Linux engine 的 glibc 下限需在 M0 实测；若高于 2.28，退路为（a）自编 engine 针对 2.28，（b）AppImage 内打包 patched glibc loader 与所需 `.so` 随应用自带。
  - **交付前核验**：对最终可执行体与 `libinksync.so` 跑 `objdump -T <bin> | grep GLIBC` 与 `ldd`，确认所有 `GLIBC_*` 版本号 ≤ 2.28（仅 `GLIBC_2.28` 及以下允许的版本号出现）。

## 2. 技术栈（锁定）
- UI：**Flutter 3.22**（自绘渲染，三端像素级一致；阅读器不走 WebView——避免 Win/WebKitGTK/系统 WebView 三套 CSS 差异，且字符级进度与高亮需直接持有文本流）。
- 原生核心：**Rust**，经 `flutter_rust_bridge` 暴露 FFI。
  - 解析：`epub`（OCF+OPF+XHTML→RichText，图片型按页渲染）、`txt`（编码嗅探）、`mobi`（文本 PalmDOC+HUFF-CDIC；漫画 KF8 图片记录抽取）、`pdf`（pdfium 文本层 + pdfrx 渲染）。
  - 同步：WebDAV client（reqwest+rustls）、HLC、三方合并。
- 本地存储：**Drift（SQLite）**，各端独立库文件，离线优先。

## 3. 格式支持矩阵（锁定）
| 类别 | 格式 | 解析方式 |
|---|---|---|
| 小说 | EPUB | 自解 OCF + OPF 元数据 + XHTML→RichText |
| 小说 | TXT | 编码嗅探（UTF-8 / 带 BOM / GB18030 兜底），按空行分章 |
| 漫画 | PDF | pdfium 文本层 + pdfrx 渲染 |
| 漫画 | MOBI / AZW3 | `mobi` crate：**KF8/AZW3 图片记录抽取**（先判 `is_drm`，加密书不支持）；文本小说 mobi 才走 PalmDOC + HUFF-CDIC 解压 |
| 漫画/小说 | EPUB | 同上；**图片型 EPUB 按图片页渲染**，进度走 `page_index` 而非 char offset |

- **CBZ/CBR 本期不在范围内**：CBZ 实现成本极低，留作后续增量；CBR 需 RAR 解码（UnRAR 许可风险），已规避。

## 4. 元数据与封面
- 来源：EPUB（OPF `dc:*` / EPUB3 `cover-image`）、MOBI（EXTH）、PDF（`/Info` + 首页缩略）、TXT（启发式取首行标题/作者）。
- 封面：EPUB2 `meta` → EPUB3 `cover-image` → 首图三级兜底；PDF 无内嵌图时渲染首页缩略图。
- 自定义封面：单独存同步文件夹 `covers/<bookId>.png`，随 WebDAV 同步，优先级高于提取封面。

## 5. 自定义高亮规则（锁定：人名 = 手动名单）
- 规则模型 `{id, name, kind, pattern, color, priority, enabled}`
  - `kind ∈ {regex, quote(双引号), booktitle(《》书名号), paren(括号), person(人名名单)}`
- `person` 类型：用户维护一份人名列表（逗号/换行分隔），编译为正则 `(名1|名2|…)`，离线零依赖。
- 管线：解析文本叶子 → 规则编译正则 → **逐叶子匹配（不跨段）** → 端点切分 + 重叠消解（高优先级胜）→ RichText 绘制。
- 持久化：规则存 SQLite，随 WebDAV `changes` 三端同步。

## 6. 跨端同步（锁定：标准 WebDAV）
- **远端布局（仅元数据，不含书库二进制）**：`inksync/{changes/<HLC>-<node>.jsonl, manifest.json, covers/<bookId>.png}`。书籍二进制留在 NAS 用户书库、以 sha256 关联；设备按需拉取并本地缓存供离线。
- **同步后端（Ryou 确认）**：极空间 NAS 开启 WebDAV 存放书籍与元数据，经「节点小宝」内网穿透供外网访问。约束：(a) WebDAV 必须 **HTTPS**，避免凭证明文过公网；(b) 元数据在 NAS 与设备**两端各存一份**，同步时直接比对；(c) 穿透链路延迟高且可能抖动，需连接重试 / 超时 / 分块上传。
- **凭据安全**：WebDAV 账号密码存系统钥匙串（Android Keystore / Windows Credential Manager / libsecret），不在明文配置或日志中落盘。
- 只追加：所有变更写 jsonl，文件名 HLC 定长编码 → 排序即时间序。
- 内容寻址：书籍以 sha256 作稳定身份（关联 NAS 书库文件），天然去重、避免重复拉取同一本。
- manifest：ETag 乐观锁，唯一并发写；冲突则重拉再合并。
- **变更发现**：拉取端用 PROPFIND 扫描 `changes/` 目录获得全部 `*.jsonl`（目录即全序），不依赖 manifest 做发现；manifest 仅存书籍元数据索引 + `last_writer_ts`。
- **设备 node id**：取安装时生成的稳定 uuid（非每次随机），保证 `changes/<HLC>-<node>.jsonl` 文件名稳定、不随运行爆炸。
- 推送安全：PUT 临时名 → MOVE 正式名；不支持 MOVE 降级 COPY+DELETE。
- **触发策略（条件化同步）**：
  - `app_launch`：拉取并合并书籍列表 / 元数据与内容变更（`changes/` + `manifest.json`）。
  - `book_open(bookId)`：打开某书时只同步该书阅读进度——先拉远端进度合并，阅读中防抖上传，关闭时做最终上传。
  - `schedule`：定时全量同步（默认 30–60 分钟，设置可调）。
  - `local_change`：本地写入后防抖（~3s）上传，出端近实时。
  - `remote_notify`（可选）：若部署轻量通知服务则收到即拉；否则依赖上述周期轮询。
- **关于「实时」**：标准 WebDAV（RFC 4918）**无服务端推送**，不依赖 WebDAV 本身做秒级同步；秒级仅在部署额外通知通道时成立。

## 7. 冲突裁决（锁定）
- **进度表示按格式分两类**（避免小说 / 漫画混用）：
  - 小说 / TXT / **reflow EPUB**：`spine` 内字符偏移（EPUB 用 CFI 最稳）；同步主键为 `(spine_index, char_offset)`。
  - 漫画 / PDF / MOBI 图片书 / **图片型 EPUB**：`page_index` + 该页 `zoom` / `scroll` 比例；无字符流，不做锚点指纹。
  - `percent` 仅作各端**展示换算**，不作为同步主键。
- 进度合并：自然阅读取 `max(percent)`，**相同 percent 时按 HLC 取最新**；forced 跳转（进度条/目录）取 HLC 最新意图。
- 小说锚点：仅小说类存视口文字指纹，对端文件版本不同时在 ±5% 字符窗口内模糊重定位；漫画类以 `page_index` 直接对齐。
- 书籍：sha256 相同 → 用远端元数据；不同 → 两版均留（重命名避免覆盖）。
- 规则/封面：按 HLC 取最新；person 名单按 id 合并。

## 8. 排序与分组（锁定：本地不同步）
- 8 种排序（书名/作者/最近阅读/添加时间/进度…）+ 6 种分组（系列/作者/标签/自定义…）。
- 仅「排序键与视图偏好」本地保存；书籍集合与分组成员关系照常同步。
- 理由：三端屏幕差异大，强制同步排序两边都难受。

## 9. 三端落地
- Android：arm64 release；文件访问用 SAF；后台同步 WorkManager。
- Windows 10：x64 MSIX/EXE；后台同步用后台 isolate + 定时器。
- UOS 20 x86_64：Linux 构建，deb / AppImage；托盘常驻做后台同步。
  - **构建环境强制 glibc 2.28**：Rust cdylib 用 `cargo zigbuild …2.28`，Flutter 产物在实测通过后交付；AppImage 自带运行库兜底。

## 10. 风险与验证清单（M0 必做）
1. 🔴 **glibc 2.28 硬约束（最高优先级）**：在 `debian:10`（glibc 2.28）容器内或 `cargo zigbuild …2.28` 产出 UOS 构件后，必须（a）在真实 UOS / glibc 2.28 环境实测能正常启动且后台同步可跑；（b）用 `objdump -T` + `ldd` 确认无任何 `GLIBC_*` > 2.28。任意一项不过则禁止交付 UOS 包。
2. `mobi` crate 版本 API 与 `core/src/formats/mobi.rs` 一致（文本 PalmDOC+HUFF-CDIC **+ 漫画 KF8 图片抽取**，含 `is_drm` 判定）。
3. `flutter_rust_bridge` 版本与 codegen 匹配；Drift 先 `build_runner` 生成 `database.g.dart`。
4. **极空间 NAS WebDAV 实测**：PROPFIND / MOVE / ETag / 路径根 行为，以及经「节点小宝」穿透链路的延迟与稳定性（HTTPS 必须）。
