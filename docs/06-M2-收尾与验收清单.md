### 2.2 Rust 核心回归测试中抓出的根因 bug（`cargo test` 发现，此前 R4.4 改写从未编译）

| 级 | 问题 | 修复 |
|---|---|---|
| 🔴 编译错误 | `highlight.rs:56` 区间切分 `*bid` 应为 `bid`（`bid` 本身是 `&str`，多解引用一层） | 改为 `bid` |
| 🔴 一致性破坏 | `regex::find_iter` 返回**字节偏移**，但 `MatchRange` 语义是「按 char 计」、Dart 侧 `allMatches` 也是 char 偏移 → 中文引号/书名号（多字节）下两端高亮区间**错位**，R4.4 名存实亡 | `cands.push` 时用 `text[..n].chars().count()` 把字节偏移转 char 偏移 |
| 🟡 测试断言 | `higher_priority_wins_overlap_region` / `quote_does_not_cross_lines` 两处断言偏移算错（off-by-one） | 修正为正确 char 偏移，并与 Dart `rule_engine_test` 对齐 |
| 🟡 测试断言 | `content_test` 非白名单标签用例误以为 `<script>` 内文本会被剥离 | 改为断言「文本保留、仅标签被消耗」 |

**修复后 `cargo test`：27 单元 + 4 集成全绿，0 warning。**（`docs/04` 命令可复现）

## 3 · 本机收口命令

```bash
cd inksync/app

# 1. 拉依赖
flutter pub get

# 2. T1：生成 Rust↔Dart FFI 绑定（codegen 版本必须与 pubspec 锁定的 2.0.0-dev.0 一致）
dart pub global activate flutter_rust_bridge_codegen 2.0.0-dev.0
flutter_rust_bridge codegen generate

# 3. T2：生成 drift 数据库代码
dart run build_runner build --delete-conflicting-outputs

# 4. 验证
flutter analyze          # 期望：零错误
flutter test             # T7：content / rule_engine / cross_end(skip 占位)

# 5. 真机起应用，过 M2 验收六条（见 §4）
flutter run -d windows
```

> `cross_end_test` 会 `markTestSkipped`：放一份 `assets/samples/sample.epub` 并接入真实
> `InksyncCore` 后，把占位改为真实双端断言（比对 `chapters.length`/`totalChars`/`char_start` 序列）。

## 5 · 已知约束与待办

- **Windows 构建**：pdfrx 需开 **Developer Mode**（用符号链接），否则 `flutter build` 失败。
- **UOS 20**：需带 **PDFium 共享库**；glibc 2.28 硬约束（Rust 用 `cargo zigbuild …2.28`，Flutter engine 需 M0 实测）。
- **T1/T2 codegen 产物**：沙箱无法生成，验收前务必在本机跑 §3 的 2、3 步。
- **M3 同步引擎**：`sync` feature 需带 C 编译器（mingw-w64 / UOS gcc）才能编译（见 `docs/04` §4），
  沙箱不可验；且按既定偏好，**M3 仍应先出定稿文档再动手**。
- **双端一致性测试**：`cross_end_test` 待内置 EPUB fixture 后启用（算法级已由 `rule_engine_test` 覆盖）。
