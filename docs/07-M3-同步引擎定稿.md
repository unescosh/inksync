## 1. M3 范围与目标

- 用户能在「同步设置」录入 WebDAV 地址/账号/密码（安全存储），一键连通后三端（Android / Windows 10 / UOS 20）实时近同步。
- 冲突按字段级三方合并裁决，不静默覆盖，可在「同步中心」回看冲突留痕。
- 书籍原文件按 sha256 内容寻址，跨端秒传、天然幂等、防损坏（下载校验）。
- 离线可用：离线修改入 outbox，联网后自动追平；墓碑软删防止离线端复活。
- UOS 20 必须产出 **glibc 2.28** 兼容二进制（硬约束，见 `03`）。

## 3. 关键技术决策回顾（与 `02`/`03` 一致）

- **HLC 而非墙上时钟**：三端系统时间可能差分钟级，HLC `{wallMs}-{counter}-{node}` 定长编码，字符串排序即时间序，配合 WebDAV `changes/<HLC>-<node>.jsonl` 文件名天然全序。
- **内容寻址 + 追加日志**：书籍按 sha256 存 blob；变更只追加 `.jsonl`，文件名排序即得时序，一次 PROPFIND 拉全。
- **manifest 乐观锁**：`manifest.json` 用 `If-Match` + ETag，412 则整轮重拉重试（最多 5 次）。
- **字段级三方合并**：base 快照存于 `syncStates`（`base.<table>.<id>`），local/remote 各自相对 base diff，并发改不同字段同时保留；进度不 LWW（取 max，强制跳转按最新意图）；membership 加并集、删才删。
- **墓碑软删**：永不物理删行，防离线端复活。

## 5. 风险与开放问题

- **沙箱不能跑 Flutter / Rust-C**，所有 `flutter analyze`/`flutter test`/UOS 包只能在用户机验证；本文件与 `06` 的命令清单即为此准备。
- **Dart 与 Rust 同步实现持续双份维护**：任何合并逻辑改动必须同步两侧并加一致性测试（T3/T5），否则会出现「某端合并结果不一致」的隐蔽 bug。
- **WebDAV 服务端差异**：各 NAS（群晖/Nextcloud）对 MOVE/PROPFIND Depth/ETag 实现不一，T1 连通性自检要覆盖典型服务端；`webdav_client.dart` 已做 COPY+DELETE 降级与 404 容错，T4 实测补边界。
- **大书架 manifest 膨胀**：`_buildManifest` 已截断到最近 200 批次；若用户量极大需评估归档策略（开放问题，非 M3 阻塞）。
