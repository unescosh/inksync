# 01 · 技术架构与选型

## 1. 结论

| 层 | 选型 | 理由 |
|---|---|---|
| UI / 业务 | **Flutter 3.22+（Dart 3）** | 一套代码覆盖 Android / Windows / Linux(UOS)；自绘渲染，三端像素一致 |
| 格式解析 / 同步协议 | **Rust（`inksync_core`）** 经 `flutter_rust_bridge` 暴露 | MOBI/AZW3 的 HUFF-CDIC、GBK/Big5 编码、PDF 文本层，Dart 生态无成熟库；Rust 三端产物一致 |
| 本地存储 | **Drift（SQLite）** | Android / Windows / Linux 均可用（`sqlite3_flutter_libs`）；强类型 DAO、迁移方便 |
| 文件存储 | 内容寻址 `blobs/<sha256[0:2]>/<sha256>` | 书籍文件不可变 → 天然免去同步冲突 |
| 网络 | `reqwest`（Rust 侧）/ `dio`（Dart 侧） | WebDAV 需要 PROPFIND / MKCOL / MOVE，普通 HTTP 客户端需自行封装 |
| 状态管理 | `riverpod` | 三端一致、可测试 |
| PDF 渲染 | `pdfrx`（PDFium） | 少有的同时支持 Android / Windows / Linux 的 PDF 渲染插件 |

### 为什么不是其他方案

- **Electron / Tauri**：没有 Android。
- **Qt 6**：UOS 上最亲和，但 Android 端投入产出比极差，且 QML 排版能力对"字符级自定义高亮"不友好。
- **Compose Multiplatform**：桌面端依赖 JVM，UOS 政企机常无 JRE，包体 +80MB，启动慢。
- **.NET MAUI / Avalonia**：Linux 桌面支持缺位或不支持 Android。
- **纯 Dart（不用 Rust）**：MOBI 需要自己实现 PalmDOC + HUFF-CDIC 解压（约 800 行且极易出错），PDF 文本层更无从下手。引入 Rust 反而降低总工作量。

## 2. 分层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层  Flutter Widgets                                       │
│   书架(排序/分组/拖拽) │ 阅读器 │ 规则编辑器 │ 同步中心 │ 导入 │
├──────────────────────────────────────────────────────────────┤
│ 领域层  Dart                                                  │
│   BookRepository   SyncEngine   RuleEngine   ProgressLocator  │
│   ├ 排序/分组策略（本地偏好，不同步）                          │
│   └ 变更捕获：所有写操作 → outbox 表（同步的唯一事实来源）     │
├──────────────────────────────────────────────────────────────┤
│ 数据层  Drift/SQLite + 文件仓库（blobs/ + covers/）           │
├──────────────────────────────────────────────────────────────┤
│ 原生核心  Rust (flutter_rust_bridge)                          │
│   formats: epub | txt(编码嗅探+分章) | mobi/azw3 | cbz | pdf   │
│   meta+cover 抽取 │ 文本归一化 │ WebDAV 客户端 │ HLC │ 合并   │
└──────────────────────────────────────────────────────────────┘
         Android: libinksync_core.so   Windows: inksync_core.dll
         UOS/Linux: libinksync_core.so
```

**边界原则**：Rust 只做「纯计算 + IO」，不持有 UI 状态；Dart 只做「状态 + 渲染」。所有跨边界数据用 `serde` ↔ `freezed/json` 的 DTO 传输（FRB 自动生成）。

## 3. 格式支持矩阵

| 格式 | 解析实现 | 元数据源 | 封面来源 |
|---|---|---|---|
| EPUB 2/3 | `zip` + `roxmltree` 解析 OPF | `<dc:*>` + `<meta>`（含 `calibre:series`） | `meta[name=cover]` → manifest；否则首张 `image/*` |
| TXT | BOM → `chardetng` → 中文默认 GBK | 文件名推断 + 首行 `# title` / `作者：` 约定 | 无（生成文字封面） |
| MOBI / AZW3 | `mobi` crate（PalmDOC + HUFF-CDIC） | EXTH（108=contributor、106=pubdate…） | EXTH 201/202 的 coveroffset |
| PDF | 渲染 `pdfrx`；文本层 `pdfium-render` | PDF `/Info` dict（Title/Author/Subject） | 首选首页渲染缩略图（`pdfium` 渲染 300px 宽 JPEG） |
| CBZ | `zip` 自然排序 | 文件名 + 可选 `ComicInfo.xml` | 第一张图 |
| CBR | ⚠️ RAR 为专利格式 | — | — |
| | 建议：① 提示用户转 CBZ；② 或 FFI 集成 `unarr`（LGPL） | | |

> **CBR 决策**：不内置 RAR 解码。导入 CBR 时弹出「一键转换为 CBZ」（本地转换，不上传），转化率 >95%，避免法律风险与体积膨胀。

## 4. 阅读引擎：为什么不用 WebView

| 维度 | WebView 方案 | 自建排版（本方案） |
|---|---|---|
| 三端一致性 | ❌ Windows=WebView2、UOS=WebKitGTK(2.28 老版本)、Android=系统 WebView，CSS 支持差异大 | ✅ 全部由 Skia 绘制 |
| 自定义高亮 | ⚠️ 需注入 JS + Range API，性能差、跨端行为不一 | ✅ 直接生成 `TextSpan`，字符级精确 |
| 进度计算 | ❌ 依赖 DOM 位置，跨端对不齐 | ✅ 统一用**字符偏移**，可跨端对齐 |
| 分页准确性 | ❌ 依赖 CSS 分页，各端不同 | ✅ 自绘测量，可离线预分页 |
| 代价 | 低 | 需自己实现 ~2000 行的排版器（已在 `reader/` 给出骨架） |

### 4.1 内容管线

```
原始文件 → Rust 解析 → RawChapter{ xhtml(归一化), plain }
        → Dart 轻量 HTML 解析 → ContentBlock[]（paragraph/heading/quote/image）
        → RuleEngine 打标 → Span[]（start/end/ruleId）
        → 组装 InlineSpan → RichText → 分页（预测量）或连续滚动
```

**归一化 XHTML 白名单**（Rust 侧输出，Dart 侧解析只需处理这几种标签）：
`p` `br` `h1`~`h6` `blockquote` `em` `strong` `img[src]` `hr`
`script/style/svg/object/iframe` 及所有 `on*` 属性一律剥离；`<img src>` 改写为 zip 内相对路径，由 Dart 从本地 zip 或缓存目录读取。

### 4.2 分页与性能

- **预分页**：首次打开章节时在 `Isolate.run` 中用 `TextPainter` 离线测量，生成 `pageSplits: Int32Array`（每页起始字符偏移）。10 万字章节 ≈ 300~600ms，缓存到 SQLite。
- **连续滚动模式**：不分页，`CustomScrollView` + 占位高度，适合长文。
- **漫画（CBZ/PDF）**：不参与文本排版，走 `PageView` + 预解码（前后各 2 页），`ResizeImage` 限制解码尺寸避免 OOM。
- **缓存**：`{bookId, chapter, ruleSetHash, fontSize, fontFamily, width} → spans/pageSplits`，任一变化即失效。LRU 上限 30 章。

## 5. 数据模型（本地 SQLite）

```
books             id(PK uuid) sha256 format title subtitle author publisher
                  language series seriesIndex description tags(json)
                  coverPath coverSource(embedded|custom|generated) coverHash
                  fileSize totalChars addedAt updatedAt
                  hlc updatedBy deleted(墓碑) deletedAt   ← 同步字段

reading_progress  bookId(PK) locatorJson percent charOffset anchorText
                  forced(bool) updatedAt hlc updatedBy

collections       id name sortOrder color emoji hlc updatedBy deleted
book_collections  bookId collectionId sortOrder hlc updatedBy deleted

highlight_rules   id name kind pattern colorValue bold italic underline
                  bgOpacity priority scope enabled sortOrder
                  hlc updatedBy deleted

sync_outbox       seq(AUTOINC) entityType entityId op payloadJson hlc createdAt
sync_state        key(PK) value     ← lastAppliedHlc / manifestEtag / deviceId
```

**每张业务表都带 `hlc` + `updatedBy` + `deleted`**，这是冲突合并的全部依据；`sync_outbox` 是待推送队列，推送成功后按 `seq` 删除。

## 6. 阅读进度定位器（跨端对齐的关键）

```jsonc
// Locator（按 format 分派）
{ "v": 1,
  "kind": "epub", "spine": 12, "char": 3481, "cfi": "epubcfi(/6/4[chap12]!/4/2,/1:3481)",
  "percent": 0.4123, "anchor": { "before": "…他终于开口", "after": "声音很轻…" } }
{ "kind": "txt",  "byte": 120394, "char": 60197, "percent": 0.33, "anchor": {...} }
{ "kind": "pdf",  "page": 87, "dy": 0.42, "percent": 0.51, "anchor": {...} }
{ "kind": "cbz",  "page": 43, "percent": 0.86 }
```

**`anchor` 是必须的**：三端字体/屏幕宽度不同，`char` 偏移不能保证落在同一句。当对端的本地文件版本（sha256）与写入方不一致时，用 anchor 做**模糊重定位**——在 `char ± 5%` 窗口内做最长公共子串匹配，取相似度最高的位置。这条做不好，用户就会出现"手机上读到第 3 章，电脑上打开跳到第 1 章"的体验灾难。

## 7. 自定义高亮规则引擎

```dart
enum RuleKind { regex, quote, bookTitleMark, personName, dialogue, keywordList }

class HighlightRule {
  final String id, name;
  final RuleKind kind;
  final String pattern;      // regex 源，或关键词表的换行分隔文本
  final bool caseSensitive, wholeWord, multiline;
  final int colorValue;      // 前景/描边色
  final int bgColorValue; final double bgOpacity;
  final bool bold, italic, underline, strike;
  final int priority;        // 重叠时高优先级胜出
  final Set<RuleScope> scope; // novel | comic | all
  final bool enabled; final int sortOrder;
}
```

内置预设（可一键启用 / 用户可改）：

| 预设 | 正则 |
|---|---|
| 中文双引号 | `[“"](?:[^“”"]{1,200}?)[”"]` |
| 直角引号 | `「[^」]{1,200}?」` |
| 书名号 | `《[^》]{1,60}?》` |
| 对话（行首至冒号） | `(?m)^[^“"《\n]{0,20}[：:]` |
| 拟声/强调 | `【[^】]+】` |

**重叠消解算法**：把所有命中的 `(start, end, priority, ruleId)` 收集后，取所有端点做**区间切分**，每个最小区间取 `priority` 最高者着色，最后合并相邻同规则的区间。复杂度 O(n log n)，n = 命中总数（一章 5 千字 × 20 条规则 ≈ 数千），实测 <5ms。

**人名高亮**：不做分词（Dart 无好用分词库，且三端词典体积大）。提供两种机制：
1. 用户维护**人名表**（可导出/随同步共享）；
2. 「从目录/正文一键提取候选」——统计高频 2~4 字片段 + 姓氏表前缀匹配，用户勾选后自动入表。

规则**随 WebDAV 同步**（`highlight_rules` 表），三端共用一套。

## 8. 非功能指标

| 项 | 目标 |
|---|---|
| 冷启动（Android 中端机） | < 1.2s |
| 章节打开（已缓存分页） | < 80ms |
| 10 万字 EPUB 导入 | < 2.5s（isolate） |
| 100MB CBZ 首次同步 | 取决于服务端；本地仅做 sha256 校验，不重复上传 |
| 安装包 | Android ~28MB(arm64 单 ABI) / Windows ~45MB / UOS ~50MB |
| 内存 | 阅读态 < 180MB |
